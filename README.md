# イベントシフト リマインド Discord BOT

Googleスプレッドシートに書いたシフト表をもとに，担当者へDiscordでリマインドを送るBOTです．

Googleアカウントがあれば無料で使えます．

## どんなものか

「誰が」「いつ」「どの持ち場に」入るのかをスプレッドシートに書いておくと，
このBOTが交代の前にDiscordへリマインドを送ってくれます．

- 担当者を **Discordのメンションで呼び出す**ので，交代を忘れたまま時間が過ぎない
- 交代の直前には，**いま入っている人にも声がかかる**ので引き継ぎができる
- その日の朝に，**全員ぶんのシフトが一覧で届く**
- その日の最終コマが終わると，**「お疲れさまでした」が届く**
- 日付・時刻・担当者は**すべてプルダウンから選ぶ**ため，表記がゆれない
- 通知を送った枠は**チェックボックスが自動で入る**ので，送信状況が一目で分かる
- シフト表と名簿のスプレッドシートは**BOTが自動で作る**（手作業で列を作る必要がない）

**準備日・本番1日目・本番2日目…と，何日でも扱えます．**
日ごとに時間帯を自由に決められるため，
「準備日は13時から，本番は9時から」といった書き分けができます．

学園祭・展示会・イベント運営を想定して作っていますが，
**「1日を時間で区切って，複数人が持ち場を交代する」用途**であれば，
設定ファイルの文面を書き換えるだけで使えます．

**このリポジトリにシフトのデータは含まれていません．** シフト表と名簿は利用者が自分で用意します．

## 届くメッセージ

コマ開始の1時間前:

```text
【60分後のシフト】10:00〜11:00
@山田 太郎、@鈴木 花子
そろそろ準備をお願いします。
```

コマ開始の15分前（交代の案内つき）:

```text
【まもなく交代】10:00〜11:00
次の担当: @山田 太郎、@鈴木 花子
持ち場へ移動をお願いします。
現在の担当: @佐藤 一郎 … 引き継ぎをお願いします。
```

その日の朝（1通にまとめて）:

```text
【本日のシフト】11月1日(日) 準備の日 7:00〜20:00
@佐藤 一郎
  9:00〜10:00
@山田 太郎
  10:00〜11:00 / 14:00〜15:00
@鈴木 花子
  10:00〜11:00

体調に気をつけて，よろしくお願いします。
```

朝のまとめは**人ごとにまとめて1通**で届きます．
コマ順に並べると自分の出番を探すのに全部読むことになるためです．

その日の最終コマが終わったとき:

```text
【本日の業務終了】11月1日(日) 準備の日 7:00〜20:00
本日の業務は終了です。お疲れさまでした。
片付けと戸締まりをお願いします。

本日の担当: @山田 太郎、@鈴木 花子、@佐藤 一郎
```

終了の時刻は**シフト表から拾う**ため，日ごとに違っていても合います．

## 使いはじめる

[docs/getting_started.md](docs/getting_started.md) に沿って進めます．
おおまかには次の順です．

1. Discord の Webhook URL を用意する
2. Apps Script プロジェクトを作り，`gas/` の中身を貼る
3. `config_shift.gs` に Webhook URL を書く
4. `create_shift_spreadsheet` を実行してシートを作る
5. 日程シートに，その日が何の日かを書く
6. 名簿に名前と Discord ID を書く
7. シフト表をプルダウンで埋める
8. `setup_triggers` を実行してトリガーを登録する

## しくみ

```
日程シート（その日が何の日か）
      │  日付の候補になる
      ▼
シフト表（1行 = 1つのコマ枠，プルダウンで埋める）
      │
      │  shift_reminder_main（15分おき）
      │    … 今日の予定・事前通知・お疲れさま
      ▼
   Discord
```

**1行を1つのコマ枠**にしているのが，この表の作りかたの中心です．

日ごとにシートを分けると，日数が増えるたびにシートが増え，
集計も通知もシートの数だけ書くことになります．
1枚の縦持ちにしておけば，日数が増えても行が増えるだけで済みます．

15分おきに動き，そのつど「いま送るものはあるか」を判定します．
通知の時刻は日程シートに書くため，トリガーは1本で足ります．

Apps Script のトリガーは指定した時刻ちょうどには動きません．
そのため前後に幅（既定は8分）を持たせて取りこぼしを防いでいます．
**幅はトリガーの間隔の半分以上が要ります．**
狭い値を設定した場合は，自動で半分まで広げます．

シフトの時刻を15分刻みにしているのは，この間隔と揃えるためです．
細かい刻みにする場合は `triggerMinutes` も細かくしてください．

## スプレッドシートの形式

3つのシートでできています．詳しくは [docs/sheet_format.md](docs/sheet_format.md) を見てください．

| シート | 役割 |
|---|---|
| 日程 | その日の予定・作業時間帯・通知時刻．全体の通知停止 |
| シフト表 | コマ枠と担当者 |
| 名簿 | 名前・Discord ID・担当コマ数 |

シフト表は最初から30行あり，プルダウンで埋めていきます．

**日程シート**に，その日が何の日かを書きます．

| 日付 | その日の予定 | 作業開始 || 作業終了 || 予定を送る || 送信済 | お疲れさまを送る || 送信済 |
|---|---|---|---|---|---|---|---|---|---|---|---|
| | | 時 | 分 | 時 | 分 | 時 | 分 | | 時 | 分 | |
| 11/1 | 準備の日 | 07 | 00 | 20 | 00 | 06 | 30 | ☐ | 20 | 00 | ☐ |
| 11/2 | Day1 本番 | 09 | 00 | 18 | 00 | | | ☐ | | | ☐ |

**作業時刻と通知時刻は別のもの**です．
作業開始・終了はその日に何時から何時まで動くかで，通知文に出ます．
「予定を送る」「お疲れさまを送る」は通知そのものの時刻です．

準備日は7時開始だから予定は6時半に，本番日は9時開始だから8時に，
というように日ごとに変えられます．

通知時刻を空にすると，作業時刻から決まります
（予定は作業開始の30分前，お疲れさまは作業終了と同じ時刻）．
送ると「送信済」にチェックが入り，外せばもう一度送れます．

**シフト表**は，日程に書いた日から選んで埋めます．

| No. | 日付 | 開始時刻 || 終了時刻 || 1人目〜 |
|---|---|---|---|---|---|---|
| | | **時** | **分** | **時** | **分** | |
| 1 | 11/2 | 10 | 30 | 12 | 00 | 山田 太郎 … |

分は15分刻み（`00` `15` `30` `45`）で，開始と終了を選ぶため
**コマの長さは自由**です．1時間でも30分でも1時間15分でも作れます．

## 通知のタイミング

`config_shift.js` の `beforeMinutes` で決めます．

```js
beforeMinutes: [60, 15],   // 1時間前と15分前
```

シフト表の「通知済み」は1列のままで，**すべて送り終えたときにチェックが入ります．**
列がタイミングの数だけ増えることはありません．

```js
beforeMinutes: [60, 30, 15],   // 30分前を足す
beforeMinutes: [15],           // 直前だけ
```

いちばん短いもの（既定では15分前）が「交代の案内」になり，
`includeCurrentShift` が `true` のとき，いま入っている担当者も併記されます．

「今日の予定」と「お疲れさま」を送る時刻は，**日程シートに書きます．**
日ごとに変わるため，config には置いていません．

## 通知を止める

止めたい範囲によって，操作する場所が違います．

| 止めたい範囲 | 場所 | 操作 |
|---|---|---|
| すべて | 日程シートの「通知を停止」 | チェックを入れる |
| その枠だけ | シフト表「通知しない」 | チェックを入れる |

**いずれもスプレッドシート側にあります．**
当日その場でスマホから切り替えられ，再デプロイが要らないようにするためです．

Discord ID が空の人は，シフト表からは消えません．
通知文には名前だけが出るため，誰が担当なのかは分かったままになります．

## 文面を変える

`gas/messages.js` を編集します．`config_shift.js` には文面を書きません．

用意されているものは2つです．

| 名前 | 用途 |
|---|---|
| `template` | 用途を問わない雛形 |
| `festival` | 学園祭・展示会などのイベント運営 |

自分用の文面を作る場合は，`template` をコピーして別の名前で足し，
`config_shift.js` の `messageSet` をその名前に変えます．
既存の文面を書き換える必要はありません．

文面で使える変数は `messages.js` の先頭に書いてあります．

## 設定項目一覧

`gas/config_shift.js` で設定します．

| 項目 | 内容 |
|---|---|
| `label` | 実行ログに出す表示名 |
| `webhookUrl` | Discord Webhook URL |
| `spreadsheetId` | シフト表のURL |
| `templateFolderId` | 作成先フォルダのURL（空文字ならマイドライブ直下） |
| `fileName` | 作られるスプレッドシートの名前 |
| `scheduleSheetName` | 日程シートのタブ名 |
| `shiftSheetName` | シフト表シートのタブ名 |
| `memberSheetName` | 名簿シートのタブ名 |
| `assigneeColumnCount` | 担当者列の数 |
| `minuteStep` | 分プルダウンの刻み（既定 15） |
| `fiscalStartYear` | 日付を年なしで書くときの年度 |
| `fiscalStartMonth` | 年度の開始月 |
| `notifications.beforeMinutes` | 事前通知のタイミング（何分前か） |
| `notifications.includeCurrentShift` | 交代のとき，いまの担当者も併記するか |
| `notifications.triggerMinutes` | トリガーを動かす間隔（1・5・10・15・30） |
| `notifications.toleranceMinutes` | トリガーのゆらぎを吸収する幅（分） |
| `messageSet` | 使う文面の名前 |

## 実行できる関数

Apps Script の「実行する関数」に出るものです．

| 関数 | いつ使うか |
|---|---|
| `create_shift_spreadsheet` | 最初の1回だけ．シートを作る |

## Git管理上の注意

`.clasp.json` と `gas/config_shift.js` は，**プレースホルダの状態**で
リポジトリに含めています．

自分のスクリプトIDや Webhook URL を書き込んだあとは，
その値がコミットされないよう次のようにします．

```bash
git update-index --skip-worktree .clasp.json
git update-index --skip-worktree gas/config_shift.js
```

元に戻すときは `--no-skip-worktree` です．

> **注意**
> Webhook URL を知っている人は，誰でもそのチャンネルへ投稿できます．
> 誤って公開した場合は，Discord 側でウェブフックを削除して作り直してください．

**このリポジトリに，実在の氏名・団体名・Discord ID・Webhook URL・
スプレッドシートのURLは含めません．** サンプルはすべて架空のものです．

## うまくいかないとき

まず `check_settings` を実行します．設定と表の状態が出て，テストメッセージが1通届きます．

| 症状 | 見るところ |
|---|---|
| 通知が来ない | 日程シートの「通知を停止」が入っていないか |
| 今日の予定・お疲れさまが来ない | 日程シートの「送信済」が入っていないか |
| | 日程シートに通知時刻か作業時刻が書いてあるか |
| | シフト表の「通知しない」が入っていないか |
| | 通知済みのチェックが，すでに入っていないか |
| | トリガーが登録されているか（`setup_triggers`） |
| メンションされない | 名簿の Discord ID が入っているか |
| 名前が「（ID未登録）」になる | 名簿に Discord ID を入れる |
| 日付が選べない | 日程シートに日が書いてあるか（`check_settings` の日数） |
| 日付がずれる | `fiscalStartYear` がイベントの年に合っているか |
| 送信に失敗する | Webhook URL が正しいか（`check_settings`） |
| お疲れさまがシフトより先に届く | 日程シートの作業終了が，シフトの終わりより早くないか |
| 担当コマ数が `#REF!` | `repair_member_formula` を実行する |

`check_settings` を実行すると，日程・シフト表・名簿の状態がまとめて出ます．
