## なぜ「見本の予定」が必要なのか

Googleカレンダーには，予定に色を付ける機能があります．
そして色には**自分で名前を付けられます**（「ラベル」と呼ばれます）．

たとえば紫色に「会社タスク」という名前を付けられます．

しかし困ったことに，**その名前をプログラムから読み取る方法がありません．**

```text
Googleカレンダーの画面        プログラムから見えるもの
  🟣 会社タスク   →    "5"（色番号だけ）
  🟢 アルバイト   →    "9"
  🔴 重要         →    "11"
```

プログラムに届くのは**色番号だけ**で，あなたが付けた名前は届きません．

そこでこのBOTは，逆向きに教えてもらう方式を採っています．

```text
あなた「"定例ミーティング" という予定と同じ色を，
        会社タスク と呼んでください」

BOT  「その予定を探しました．色番号は "5" でした．
        では "5" = 会社タスク として覚えます」
```

この「同じ色が付いている実在の予定」が，**見本の予定**（`sampleEventTitle`）です．

> **補足：Calendar API を使っても同じです**
> このBOTは以前 Google Calendar API を直接使っていましたが，
> そちらでもラベル名は取得できませんでした．
> 現在は `CalendarApp` だけで動作します．

## しくみの全体像

### 1回だけ行う作業（覚えさせる）

```text
config_labels.js に見本を書く
        ↓
sync_calendar_label_registry を実行
        ↓
BOTがカレンダーから見本の予定を探す
        ↓
その予定の色番号を読み取る
        ↓
「色番号 ↔ 名前」の対応表を保存する
```

保存先は **Script Properties** という，GASプロジェクトごとの保存領域です．
コードの中ではなくGAS側に保存されるため，`clasp push` しても消えません．

### 毎朝の通知のとき

```text
カレンダーから今日の予定を取る
        ↓
各予定の色番号を見る
        ↓
保存した対応表で名前に変換する
        ↓
通知したい名前かどうか判定する
        ↓
一致した予定だけメッセージに入れる
```

## 色について

Googleカレンダーのラベルには，あらかじめ用意された色のほか，
カラーピッカーで `#55b080` のように**自分で色を作る**こともできます．

**どちらでも問題なく使えます．**

このBOTは色を「名前を引くための鍵」として扱うだけで，
色の中身を解釈しません．そのため色の種類に上限はなく，
ラベルをいくつ作っても見分けられます．

```text
予定に付けた色     BOTが覚える鍵      通知での表示
  パレットの色  →   "5"          →   [会社タスク]
  #55b080      →   "#55b080"    →   [趣味創作]
  色なし        →   （空）        →   [デフォルト]
```

色番号や色コードを自分で調べる必要はありません．
`sync_calendar_label_registry` が見本の予定から自動で読み取ります．

### 守ること

**別々のラベルに同じ色を使わないでください．**

BOTは色だけで見分けているため，同じ色を2つのラベルに割り当てると区別できません．
この場合は `inspect_calendar_labels` の実行ログに
「colorId の衝突があります」という警告が出ます．

## 設定の書き方

編集するのは `gas/config_labels.js` です．書く場所は2か所あります．

### 1. 通知したい名前を並べる

```js
const CALENDAR_REMINDER_LABELS = [
  "会社タスク",
  "アルバイト",
  "重要"
];
```

ここに書いた名前の予定だけが通知されます．

### 2. それぞれの見本を書く

```js
const CALENDAR_LABEL_REGISTRY_SEEDS = [
  {
    labelName: "会社タスク",
    sampleEventTitle: "定例ミーティング",
    sampleDate: "2026/07/05"
  },
  {
    labelName: "アルバイト",
    sampleEventTitle: "アルバイト",
    sampleDate: "2026/07/08"
  },
  {
    labelName: "重要",
    sampleEventTitle: "資格試験の申し込み締切",
    sampleDate: "2026/07/06"
  }
];
```

| 項目 | 書く内容 | 注意点 |
| --- | --- | --- |
| `labelName` | 通知に表示したい名前 | 自由に決められます．カレンダー側の名前と違っても構いません |
| `sampleEventTitle` | その色が付いた予定の件名 | **カレンダー上の表示と完全に一致**させる必要があります |
| `sampleDate` | その予定の日付 | `2026/07/05` の形式．この日の**前後30日**を探します |

### 日付の書き方

`sampleDate` は **`2026/07/05`（年/月/日）** の形式で書きます．

`2026-7-5` のようにハイフン区切りでも動きますが，
ハイフン区切りは**世界標準時として解釈される**ため，日本時間との9時間のずれが内部で生じます．
探索範囲が前後30日と広いため実害はまず出ませんが，
**紛らわしいのでスラッシュ区切りに統一してください．**

| 書き方 | 判定 |
| --- | --- |
| `"2026/07/05"` | ✅ 推奨 |
| `"2026/7/5"` | ✅ 動く（0埋めなしでも可） |
| `"2026-07-05"` | ⚠️ 動くが時差のずれが生じる |
| `"07/05/2026"` | ❌ 月と日が逆に解釈される |
| `""`（空） | ✅ 今日を基準に前後30日を探す |

### 件名は完全一致

`sampleEventTitle` は**一字一句そのまま**である必要があります．

| カレンダー上の表示 | 書いた値 | 結果 |
| --- | --- | --- |
| `定例　ミーティング` | `定例ミーティング` | ❌ 全角スペースと半角スペースの違い |
| `アルバイト 14:40~16:40` | `アルバイト` | ❌ 後半が抜けている |
| `定例会` | `定例会 ` | ❌ 末尾に余計な空白 |

コピー＆ペーストで貼り付けるのが確実です．

### 3. 絞り込みを有効にする

`gas/config_calendar.js` の1行を書き換えます．

```js
targetEventLabels: false,          // すべての予定を通知
```

↓

```js
targetEventLabels: CALENDAR_REMINDER_LABELS,   // 指定した名前だけ通知
```

## 「デフォルト」という特別な名前

`デフォルト` という名前だけは特別扱いされます．
**色を設定していない予定**が，自動的にこの名前になります．

```js
const CALENDAR_REMINDER_LABELS = [
  "会社タスク",
  "デフォルト"          // 色なしの予定も通知したい場合
];
```

`デフォルト` には**見本の予定が要りません．**
`CALENDAR_LABEL_REGISTRY_SEEDS` に書く必要はありません．

| 使い方 | 結果 |
| --- | --- |
| `デフォルト` を書く | 色なしの予定も通知される |
| `デフォルト` を書かない | 色なしの予定は通知されない |

色を付け忘れた予定を拾いたい場合に使います．

## 覚えさせたあとにできること

### 見本の予定は消してよい

一度 `sync_calendar_label_registry` が成功すれば，対応表はGAS側に保存されます．
**見本にした予定をカレンダーから削除しても，通知は動き続けます．**

毎朝の通知では，**すでに覚えている色を探し直すことはありません．**
未登録のラベルがあるときだけ，そのラベルの見本を探します．

### 名前だけ変えたいとき

`labelName` を書き換えて `sync_calendar_label_registry` を実行し直すだけです．
カレンダー側の操作は要りません．

### カレンダーの色を変えたとき

**必ず `sync_calendar_label_registry` を実行し直してください．**
古い色番号のまま覚えているため，実行しないと予定が拾われなくなります．

このとき見本の予定が必要です．削除してしまっている場合は，
新しい色が付いた別の予定を見本として指定してください．

### ラベルを増やすとき

1. カレンダーで新しい色を付ける
2. `config_labels.js` の2か所に追記する
3. `sync_calendar_label_registry` を実行する

### ラベルを減らすとき

`config_labels.js` から削除して `sync_calendar_label_registry` を実行すれば，
保存された対応表からも自動的に消えます．手作業での削除は不要です．

## 制約とよくある失敗

### 制約

| 制約 | 内容 |
| --- | --- |
| 同じ色は使い回せない | 2つのラベルに同じ色を割り当てると区別できません |
| 同じ色は使い回せない | 2つの名前に同じ色を割り当てると区別できません |
| カレンダー側の名前は使えない | Googleカレンダーで付けたラベル名は読み取れません．BOT側で改めて名前を決めます |
| 見本の予定が必要 | 色ごとに1件，実在する予定を指定する必要があります |

### よくある失敗

**「サンプル予定が見つかりません」と出る**

| 原因 | 確認すること |
| --- | --- |
| 件名が違う | 全角/半角，スペースの数まで一致しているか |
| 日付が離れすぎ | `sampleDate` の前後30日以内にその予定があるか |
| 予定を消した | カレンダーにその予定が残っているか |
| カレンダーが違う | `calendarId` で指定したカレンダーにその予定があるか |

**「サンプル予定から colorId を取得できませんでした」と出る**

予定は見つかったものの，**色が付いていません．**
カレンダーでその予定に色を付けてから，もう一度実行してください．

**「次のラベルが内部レジストリへ未登録です」と出る**

`CALENDAR_REMINDER_LABELS` に書いた名前が，まだ覚えられていません．

| 確認すること | 内容 |
| --- | --- |
| 見本を書いたか | その名前の見本が `CALENDAR_LABEL_REGISTRY_SEEDS` にあるか |
| 名前が一致しているか | 2か所の `labelName` が同じ文字列か |
| 同期したか | `sync_calendar_label_registry` を実行したか |

**`calendarId` を変えたあと，色を覚え直してほしい**

覚え直しは自動です．

色番号はカレンダーごとの意味しか持たないため，`calendarId` を変えると
保存済みレジストリは破棄され，見本から色を取り直します．
実行ログに「対象カレンダーが変わったためレジストリを破棄します」と出ます．

このとき見本の予定も，**新しいカレンダー側に**色付きで用意しておいてください．

**通知に違う名前が表示される**

2つの名前に同じ色を使っています．
`inspect_calendar_labels` を実行し，ログの
「colorId の衝突があります」という行を確認してください．

**ラベル名が表示されない（`[ ]` が出ない）**

その予定の色を，まだ覚えていません．
色を付けたうえで見本を登録し，`sync_calendar_label_registry` を実行してください．

## 調べ方

うまく動かないときは，**`inspect_calendar_labels`** を実行してください．
実行ログに次が出力されます．

### 出力される内容

```text
=== ラベル診断 ===
calendarId=primary

=== 保存済みラベルレジストリ ===
seedCount=2
{"labelName":"会社タスク","sampleEventTitle":"定例ミーティング", ...}
{"labelName":"会社タスク","colorId":"5","source":"seed", ...}
{"labelName":"アルバイト","colorId":"9","source":"seed", ...}

{"title":"週次進捗確認","start":"14:30","eventLabelName":"会社タスク","colorId":"5", ...}
{"title":"買い物","start":"18:00","eventLabelName":"","colorId":"", ...}
```

### 読み方

| 見るところ | 意味 |
| --- | --- |
| `colorId` に数字が入っている | その名前の色を覚えられています |
| `colorId` が空 | まだ覚えていません．見本を確認してください |
| `source":"seed"` | 見本から覚えた，という記録 |
| `source":"config"` | 名前だけ登録され，色はまだ未取得 |
| 各予定の `eventLabelName` | その予定が，どの名前として認識されたか |
| `colorId の衝突があります` | 同じ色を2つの名前に使っています |

### 対応表を作り直したいとき

おかしくなった場合は，一度リセットできます．

1. **`clear_calendar_label_registry`** を実行する（保存された対応表が空になる）
2. **`sync_calendar_label_registry`** を実行する（見本から作り直す）

このとき見本の予定が必要です．削除している場合は，
`config_labels.js` の `sampleEventTitle` を現存する予定に書き換えてから実行してください．
