## 2つのシート

`create_roster_spreadsheet` を実行すると，1つのスプレッドシートの中に
2つのシート（タブ）が作られます．

| シート | 役割 |
| --- | --- |
| 当番表 | 誰がいつ当番かを書く．BOTはここを読んで通知する |
| 名簿 | 名前とDiscord IDの対応表．メンションに使う |

**名簿を先に埋めることを勧めます．** 当番表の担当者は名簿から選ぶ形式のためです．

## 名簿シート

| 列 | 項目 | 内容 |
| --- | --- | --- |
| A列 | `名前` | 当番表のプルダウンに出る名前 |
| B列 | `Discord ID` | メンション用のユーザーID（18桁前後の数字） |
| C列 | `メモ` | 学年や所属など．BOTは読まない |

記入例:

| 名前 | Discord ID | メモ |
| --- | --- | --- |
| 山田 太郎 | 123456789012345678 | B4 |
| 鈴木 花子 | 234567890123456789 | M1 |
| 佐藤 次郎 | | IDが未登録 |

### Discord IDの調べかた

1. Discordの「設定」→「詳細設定」→「開発者モード」を**オン**にする
2. 対象のユーザーを右クリック →「ユーザーIDをコピー」

スマートフォンの場合は，ユーザーのプロフィールを開き，
右上のメニューから「ユーザーIDをコピー」を選びます．

### IDが分からない人がいる場合

**空欄のままで構いません．** その人は，メンションされず名前だけで通知されます．

```text
来週の発表は@山田 太郎、佐藤 次郎（ID未登録）です。
```

誰のIDが足りないかは `check_settings` を実行すると一覧で確認できます．

> **補足**
> Discord IDは18桁前後の数字です．数値として扱うと桁が落ちてしまうため，
> ID列は「書式なしテキスト」に設定されています．そのままIDを貼り付けてください．

## 当番表シート

1行目が見出し，2行目以降がデータです．

| 列 | 項目 | 内容 |
| --- | --- | --- |
| A列 | `No.` | 回番号．`なし`，`補講`，`追加` などの文字も入れられる |
| B列 | `担当日` | 当番を担当する日 |
| C列 | `通知日` | この日にDiscordへ通知する．空欄なら担当日から自動計算 |
| D〜K列 | `1人目`〜`8人目` | 担当者．プルダウンから選ぶ．いない回は空欄 |
| L列 | `内容` | 発表回名やイベント名．**通知文に載る** |
| M列 | `メモ` | 自由記入欄．**通知には使わない** |
| N列 | `通知済み` | 通知を送るとチェックが入る |

記入例:

| No. | 担当日 | 通知日 | 1人目 | 2人目 | 内容 | メモ | 通知済み |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 1 | 2026/09/17 | 2026/09/11 | | | ガイダンス | 新入生歓迎会もあり | ☑ |
| 2 | 2026/09/24 | 2026/09/18 | 山田 太郎 | 鈴木 花子 | S1 | | ☐ |
| なし | 2026/10/01 | 2026/09/25 | | | 出張のため休み | | ☐ |
| 追加 | | | | | | 日程未定 | ☐ |

`No.` は数値でなくても構いません．`なし`・`補講`・`追加` のような文字も入れられます．
BOTは `No.` の内容で動作を変えません．

## 日付の入力

### カレンダーから選ぶ

日付のセルを**ダブルクリックするとカレンダーが開きます．** そこから選ぶのが確実です．

表示は `2026/09/17` のように**年まで**出ます．

### 年を省略して入力する

`9/17` のように年を省略して入力することもできます．
その場合の年は，設定ファイルの年度から決まります．

```js
fiscalStartYear: 2026,   // 年度の開始年
fiscalStartMonth: 4,     // 年度の開始月（日本の年度なら4）
```

この設定では，**年度開始月（4月）より前の月は翌年**として扱われます．

| 入力 | 解釈される日付 |
| --- | --- |
| `9/17` | 2026年9月17日 |
| `12/31` | 2026年12月31日 |
| `1/7` | **2027年**1月7日 |
| `3/1` | **2027年**3月1日 |

秋学期のように年をまたぐ場合でも，正しく判定されます．

### 通知日を空欄にする

`通知日` を空欄にすると，**担当日から自動で計算**されます．

```js
noticeOffsetDays: 7,   // 担当日の7日前を通知日にする
```

担当日が `2026/09/24` なら，通知日は `2026/09/17` として扱われます．
シートには書き込まれず，判定のときだけ使われます．

毎回同じ間隔で通知するなら，通知日の列は空のままで構いません．

### 日付が空の行

`担当日` も `通知日` も空の行は，**何もしません．**
「追加」のように予定が未定の行を置いておけます．
日程が決まって日付を入れれば，通常どおり通知されます．

## 担当者の入力

担当者のセルをクリックすると，**名簿に登録されている名前が一覧で出ます．**
そこから選んでください．

### 名簿に無い名前は入力できない

これは制限ではなく，**名前の打ち間違いを防ぐため**です．

当番表と名簿で名前が1文字でも違うと，その人はメンションされません．
プルダウンにしておけば，そもそも違う名前が入りません．

新しい人を担当者にしたい場合は，**先に名簿へ追加**してください．
名簿に行を足すと，プルダウンの候補にも自動で追加されます（BOTの再実行は不要です）．

### 担当者がいない回

**空欄のまま**にします．`-` などの記号を入れる必要はありません．

担当者が空でも `内容` が書かれていれば，イベント通知として送られます．

### 人数が回によって違う場合

埋まっているところだけが読まれます．
`1人目` と `2人目` だけ埋めて，`3人目` 以降が空でも問題ありません．

## 内容とメモの使い分け

**この2つの違いは，Discordへ送られるかどうかです．**

| 列 | 通知に載るか | 用途 |
| --- | --- | --- |
| `内容` | **載る** | S1，ガイダンス，卒業研究相談会 など |
| `メモ` | 載らない | 「〇〇さんが欠席予定」「教室変更あり」など |

`内容` は次のように通知文へ入ります．

```text
来週の発表は@山田 太郎です。よろしくお願いします。
要旨添削は月曜日の13時までに提出しましょう。
内容: S1                          ← ここ
```

担当者がいない回では，`内容` が通知の主役になります．

```text
@everyone 来週はガイダンスがあります。   ← 内容がそのまま入る
```

`メモ` は人が読むためだけの欄です．何を書いてもBOTの動作に影響しません．

## 通知済みチェックボックス

通知を送ると，その回の `通知済み` 列に**自動でチェックが入ります．**

- シート上で**送信状況が一目で分かる**
- チェックが入っている回は，次回以降スキップされる
- 同じ回が二度送られることがない

### もう一度送りたいとき

**チェックを外すだけです．** 次回の実行でまた送られます．

担当者を入れ替えたあとに送り直したい場合などに使います．

### 手でチェックを入れてもよい

送りたくない回に，あらかじめチェックを入れておけばスキップされます．

## 列の数を変える

担当者が9人以上必要な場合や，逆に4人で足りる場合は，
設定ファイルで列の数を変えられます．

```js
assigneeColumnCount: 8,   // 「1人目」〜「8人目」の8列
rosterRowCount: 20,       // データ行を20行
```

`assigneeColumnCount` を変えると，**列が自動で増減し，
右にある `内容`・`メモ`・`通知済み` の位置もずれます．**

| 設定値 | 合計の列数 |
| --- | --- |
| `4` | 10列 |
| `8` | 14列 |
| `12` | 18列 |

変更したあとは `create_roster_spreadsheet` でシートを作り直してください．

> **注意**
> 作り直すと，入力済みの内容は消えます．
> 新しい学期を始めるときなど，中身が空でよいタイミングで行ってください．

## よくある入力ミス

| 症状 | 原因 | 対処 |
| --- | --- | --- |
| 担当者が入力できない | 名簿に無い名前を入れようとしている | 先に名簿へ追加する |
| メンションされず名前だけ出る | 名簿のDiscord ID列が空 | IDを入力する．`check_settings` で一覧確認 |
| 通知が飛ばない | `通知済み` にチェックが付いている | チェックを外す |
| 日付が1年ずれる | `fiscalStartYear` が前年度のまま | 設定を更新する |
| 通知日が意図と違う | 通知日が空で自動計算されている | 通知日を直接入力するか `noticeOffsetDays` を変える |
| 内容が通知に出ない | `メモ` 列に書いている | `内容` 列へ移す |
